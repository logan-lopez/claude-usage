# Fixtures and the test suite

Every numeric assertion runs against `fixtures/`, a frozen and scrubbed copy of 24 real
transcripts that is committed. The expected numbers come from a second, independent dedup
implementation. The suite never touches live data or the network.

**Sources:** `tools/make-fixture.ts`, `fixtures/`, `tests/fixture.test.ts`, `tests/helpers.ts`

**History:** [brief 01](../briefs/archive/01-archiver-and-session-views.md)

- `tools/make-fixture.ts` (`bun run fixture`) copies a sample of the live corpus, scrubs it, and
  writes `fixtures/MANIFEST.json` (sha256 of every other file it writes) and `fixtures/BASELINE.json`
  (the expected numbers).
- `tests/helpers.ts` builds archives from the fixture, plus synthetic databases for cases the
  fixture lacks, such as a session flagged `has_unknown_model_cost`.
- `tests/fixture.test.ts` checks the fixture bytes against `MANIFEST.json`, checks the fixture
  still covers every hard case, and re-runs the leak scan.

## How it works

**The baseline.** `make-fixture.ts` contains its own short reducer that implements the dedup rule
in plain JavaScript over the committed fixture bytes:

1. keep-max;
2. then non-sidechain;
3. then the record carrying speed.

The suite asserts `src/ingest.ts` reproduces its result. The SQL UPSERT and the JavaScript reducer
are different implementations of one rule; if they disagree, one is wrong.

**Scrubbing** is an allowlist (`VERBATIM_ENVELOPE`, `KEEP_TYPES`).

- Every id, path, branch and slug is remapped.
- All message content is dropped.
- The verbatim fields that could plausibly carry text were checked against the live corpus first.
  Every distinct value of
  `entrypoint`, `version`, `effort`, `userType`, `promptSource`, `sessionKind` and the five `attribution*`
  fields is a tool, model, skill or agent name, never user text.

**The pricing calibration** fixture (`fixtures/pricing-calibration.json`) is separate and
regenerated by `tools/make-pricing-calibration.ts`. See [Cost](cost.md#decisions).

## Rules worth keeping

- **Never assert against live data.** Live data is appended to continuously and garbage collected.
  A baseline that drifts trains everyone to ignore a failing test.
- **Regenerate; never hand-edit.** `bun run fixture` rewrites `MANIFEST.json` and `BASELINE.json`
  together, so the baseline can't drift without the fixture bytes changing.
- **Keep the two dedup implementations separate.** Reading the expected numbers out of
  `src/ingest.ts`, or hard-coding numbers it produced, only proves the ingester agrees with itself.
- **Allowlist, not denylist.** A denylist leaks the first time Claude Code adds a field. A new
  field goes into the allowlist deliberately, then the leak test is re-run.
- **The leak scan runs on every `bun test`,** not once at generation time.
- **The suite is offline.** See [Network](network.md#rules-worth-keeping) for how the refresh tests
  avoid the real endpoint.
